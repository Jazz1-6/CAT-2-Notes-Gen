1. How to Use These Notes

Answer templates that work in an open-book exam

An open-book HOTs exam doesn't test memorization — it tests whether you can apply what's in the book. The graders look for reasoning, not recitation. Every answer you write should follow this shape:

Part 1 — Identify (1 line). Name the concept or algorithm. Example: "This is an AVL insertion that triggers an LL rotation."
Part 2 — Working (most marks). Numbered steps, trace table, or dry run. Don't skip. Most marks live here.
Part 3 — Result (boxed). One clear final answer. Commit to it.
Part 4 — Justify (3–5 lines). Why this result? What trade-off? What changes under perturbation? HOTs marks hide here.
The Five Reusable Answer Shapes
Question says… Template
"Trace / dry-run / show step-by-step" State assumptions → numbered steps with a small table → boxed final state → one-line "why the algorithm produced this."
"Compute X" (comparisons, swaps, height, faults) State formula → substitute numbers → show the count explicitly → boxed result → sanity check.
"Compare and recommend" Criteria table (algorithm × property) → one-line verdict per algorithm → end with "Therefore, X is recommended because…"
"What if X changes?" Answer the original case first → then the perturbed case → state whether result changed → justify why.
"Design a structure/mechanism" Name the structure → list its components → explain how they interact → state complexity → justify the choice.

3.1 Binary Tree & Binary Search Tree (BST)

In one sentence: A BST is a binary tree where every left child is smaller and every right child is larger than its parent.

A binary tree is a tree where each node has at most two children. A BST adds an ordering rule: for every node, all keys in the left subtree are smaller, and all keys in the right subtree are larger.

Analogy A BST is like a library where smaller call numbers are always to the left and larger ones to the right. To find a book, you halve the search space at every shelf.
Why you'd use this Use a BST whenever you need to keep data sorted AND support fast insert/delete/search. When you need guaranteed O(log n), upgrade to an AVL tree (3.2).
Key rules Search / Insert / Delete: O(h), h = tree height. Balanced: h = O(log n). Skewed: h = O(n).
Min = leftmost node. Max = rightmost node. Inorder of BST = sorted.
BST Insert — C 
struct Node { int key; struct Node *left, *right; };

struct Node* insert(struct Node* root, int key) {
    if (root == NULL) {
        struct Node* n = malloc(sizeof(struct Node));
        n->key = key;
        n->left = n->right = NULL;
        return n;
    }
    if (key < root->key)
        root->left = insert(root->left, key);
    else if (key > root->key)
        root->right = insert(root->right, key);
    return root;
}
BST Delete — Three Cases
Case What to do
Leaf Remove it. Set parent's pointer to NULL.
One child Bypass it. Parent points to the only child.
Two children Replace with inorder successor (leftmost of right subtree), then delete the successor node.
Worked Example — Build BST from: 50, 30, 70, 20, 40, 60, 80
Step Insert Action
1 50 Root.
2 30 30 < 50 → left of 50.
3 70 70 > 50 → right of 50.
4 20 20 < 50, < 30 → left of 30.
5 40 40 < 50, > 30 → right of 30.
6 60 60 > 50, < 70 → left of 70.
7 80 80 > 50, > 70 → right of 70. 
              50
             /  \
           30    70
          /  \  /  \
         20  40 60  80

Inorder:  20, 30, 40, 50, 60, 70, 80    ✓ sorted
Search 40:  50 → 30 → 40        = 3 comparisons (found)
Search 65:  50 → 70 → 60 → NULL = 4 comparisons (not found)
What if…? Insert same keys in sorted order (10, 20, 30, 40, 50) → BST becomes right-skewed chain of height n−1. Search degrades from O(log n) to O(n).
Common mistake Confusing "binary tree" (no ordering) with "BST" (ordering). Also: inorder successor is the leftmost of right subtree, not always the right child.

3.2 Height-Balanced Trees — AVL

In one sentence: An AVL tree is a BST that stays balanced by rotating subtrees whenever a node's children differ in height by more than 1.

AVL trees enforce: |height(left) − height(right)| ≤ 1 at every node. Balance factor (BF) = height(left) − height(right). If insert pushes BF to ±2, a rotation restores balance.

Analogy Think of a mobile hanging from the ceiling. Adding a weight tilts it. AVL's rotations are the strings re-adjusting so the mobile hangs level again.
Why you'd use this Use AVL whenever you need guaranteed O(log n) operations. A plain BST can degrade to O(n) on sorted input; AVL cannot.
Key rules Height bound: h ≤ 1.44 · log₂(n + 2) − 0.328 → h = O(log n).
Key fact: a single insertion causes at most one rotation.
The Four Rotation Types
Case Condition Fix
LL BF > 1, left child BF ≥ 0 Single right rotation at unbalanced node
RR BF < −1, right child BF ≤ 0 Single left rotation at unbalanced node
LR BF > 1, left child BF < 0 Left-rotate left child, then right-rotate node
RL BF < −1, right child BF > 0 Right-rotate right child, then left-rotate node
Worked Example — Insert 10, 20, 30, 40, 50 into empty AVL
Step Insert What happens
1 10 Empty → 10 root.
2 20 20 > 10 → right of 10. BF(10) = −1, OK.
3 30 30 > 10, > 20. BF(10) = −2 → RR case. Left-rotate at 10 → 20 root.
4 40 40 > 20, > 30 → right of 30. All BF OK.
5 50 50 > 40. BF(30) = −2 → RR case. Left-rotate at 30 → 40 new root of that side. 
              20
             /  \
           10    40
                /  \
              30    50

Height = 2 for 5 nodes (minimum possible).
What if…? Insert 25 instead of 30 → triggers LR case at node 10. Left-rotate left child (20), then right-rotate node (10). Result: 20 becomes root with 10 and 25 as children.

3.3 Threaded Binary Trees

In one sentence: A threaded binary tree uses the NULL pointers as shortcuts to the inorder successor or predecessor, letting you traverse without a stack.

Key rules Right-threaded: NULL right → inorder successor. Left-threaded: NULL left → inorder predecessor. Fully-threaded: both.
Traversal: O(n) time, O(1) extra space.
Inorder Traversal Without a Stack — C 
struct Node {
    int key;
    struct Node *left, *right;
    int rightThread;               /* 1 if 'right' is a thread */
};

struct Node* leftmost(struct Node* n) {
    while (n != NULL && n->left != NULL) n = n->left;
    return n;
}

void inorder(struct Node* root) {
    struct Node* cur = leftmost(root);
    while (cur != NULL) {
        printf("%d ", cur->key);
        if (cur->rightThread)
            cur = cur->right;             /* thread → successor */
        else
            cur = leftmost(cur->right);   /* real right child */
    }
}

3.4 Tries (Prefix Trees)

In one sentence: A trie stores strings character-by-character along tree edges, so lookup time depends only on string length, not the number of stored strings.

Analogy Tries are how predictive text works. Type "ca" and it knows the next letters lead to "cat", "car", "card" — because those words share the "ca" path.
Key rules Search / Insert / Delete: O(m), m = key length. Space: O(m × alphabet). No collisions.
Trie Insert — C 
#define ALPHA 26

struct TrieNode {
    struct TrieNode* child[ALPHA];
    int isEnd;
};

struct TrieNode* newTrieNode() {
    struct TrieNode* n = malloc(sizeof(struct TrieNode));
    n->isEnd = 0;
    for (int i = 0; i < ALPHA; i++) n->child[i] = NULL;
    return n;
}

void insert(struct TrieNode* root, const char* word) {
    struct TrieNode* cur = root;
    for (int i = 0; word[i]; i++) {
        int idx = word[i] - 'a';
        if (!cur->child[idx])
            cur->child[idx] = newTrieNode();
        cur = cur->child[idx];
    }
    cur->isEnd = 1;
}

3.5 Heaps (Binary Heap)

In one sentence: A heap is a complete binary tree stored in an array where every parent is smaller (min-heap) or larger (max-heap) than its children.

Key rules For index i (0-based): left = 2i+1, right = 2i+2, parent = ⌊(i−1)/2⌋.
Insert / Extract: O(log n). Peek: O(1). Build: O(n).
Heapify-Down and Build — C 
void minHeapify(int a[], int n, int i) {
    int smallest = i, l = 2*i + 1, r = 2*i + 2;
    if (l < n && a[l] < a[smallest]) smallest = l;
    if (r < n && a[r] < a[smallest]) smallest = r;
    if (smallest != i) {
        int t = a[i]; a[i] = a[smallest]; a[smallest] = t;
        minHeapify(a, n, smallest);
    }
}

void buildMinHeap(int a[], int n) {
    for (int i = n/2 - 1; i >= 0; i--)
        minHeapify(a, n, i);
}
Worked Example — Build Min-Heap from [9, 4, 7, 1, 3, 8]
Step i a[i] Children Swap? Array after
2 7 a[5] = 8 No [9, 4, 7, 1, 3, 8]
1 4 a[3]=1, a[4]=3 Yes (1) [9, 1, 7, 4, 3, 8]
0 9 a[1]=1, a[2]=7 Yes (1) [1, 9, 7, 4, 3, 8]
recurse 1 9 a[3]=4, a[4]=3 Yes (3) [1, 3, 7, 4, 9, 8]
Min-heap = [1, 3, 7, 4, 9, 8]
Build is O(n) — most nodes near leaves need little sifting.

3.6 Hash Tables

In one sentence: A hash table maps keys to array indices via a hash function, giving O(1) average lookup but O(n) worst case when many keys collide.

Key rules Load factor: α = n/m. Chaining: avg O(1+α), worst O(n). Open addressing: requires α < 1.
Good hash: h(k) = k mod m, m prime.
Worked Example — Insert 10, 22, 31, 4, 15 into size-7 table (h(k) = k mod 7)
Key h(k) Chaining Linear Probing
10 3 bucket 3 = [10] slot 3 = 10
22 1 bucket 1 = [22] slot 1 = 22
31 3 bucket 3 = [10, 31] 3 → 4 → 5 → place at 5
4 4 bucket 4 = [4] slot 4 = 4
15 1 bucket 1 = [22, 15] 1 → 2 → place at 2
Linear table = [_, 22, 15, 10, 4, 31, _]; α = 5/7 ≈ 0.71
Common mistake Open addressing needs tombstones on deletion, not plain NULL. Otherwise searches stop early and miss keys inserted after a deleted one.

3.7 BFS & DFS

In one sentence: BFS explores level by level (using a queue); DFS goes deep before backtracking (using a stack or recursion).

Key rules Adjacency list: O(V+E). Adjacency matrix: O(V²).
BFS finds shortest path (unweighted). DFS detects cycles, gives topo order.
BFS and DFS — C 
void bfs(int start, int V) {
    int q[MAXV], front = 0, rear = 0;
    for (int i = 0; i < V; i++) visited[i] = 0;
    visited[start] = 1;
    q[rear++] = start;
    while (front < rear) {
        int u = q[front++];
        printf("%d ", u);
        for (int i = 0; i < deg[u]; i++) {
            int v = adj[u][i];
            if (!visited[v]) { visited[v] = 1; q[rear++] = v; }
        }
    }
}

void dfs(int u, int V) {
    visited[u] = 1;
    printf("%d ", u);
    for (int i = 0; i < deg[u]; i++) {
        int v = adj[u][i];
        if (!visited[v]) dfs(v, V);
    }
}
Worked Example — Edges: 0–1, 0–2, 1–3, 2–3, 3–4 
Adjacency:
  0: [1, 2]   1: [0, 3]   2: [0, 3]   3: [1, 2, 4]   4: [3]

BFS from 0:  0 → 1 → 2 → 3 → 4
DFS from 0:  0 → 1 → 3 → 2 → 4

3.8 Topological Sort & DAGs

In one sentence: Topological sort orders the vertices of a DAG so that every edge u→v has u before v.

Key rules Kahn's algorithm: compute indegrees → queue indegree-0 nodes → pop, output, decrement successors.
Complexity: O(V+E). Not unique.
Worked Example — Edges: 5→0, 5→2, 4→0, 4→1, 2→3, 3→1
Step Queue Output Indegrees after
init [4, 5] — 0:2, 1:2, 2:1, 3:1, 4:0, 5:0
pop 4 [5] 4 0:1, 1:1
pop 5 [0, 2] 5 0:0, 2:0
pop 0 [2] 0 —
pop 2 [3] 2 3:0
pop 3 [1] 3 1:0
pop 1 [] 1 done
Topo order = 4, 5, 0, 2, 3, 1

3.9 Union-Find (Disjoint Set Union)

In one sentence: Union-Find tracks disjoint sets with near-constant-time merge and find operations.

Key rules Naive: O(n). Union by rank alone: O(log n). Path compression alone: O(log n) amortized. Both: O(α(n)) amortized.
Union-Find with Both Optimizations — C 
int parent[MAXV], rnk[MAXV];

void makeSet(int n) {
    for (int i = 0; i < n; i++) { parent[i] = i; rnk[i] = 0; }
}

int find(int x) {
    if (parent[x] != x)
        parent[x] = find(parent[x]);   /* path compression */
    return parent[x];
}

void unionSets(int x, int y) {
    int rx = find(x), ry = find(y);
    if (rx == ry) return;
    if (rnk[rx] < rnk[ry]) parent[rx] = ry;
    else if (rnk[rx] > rnk[ry]) parent[ry] = rx;
    else { parent[ry] = rx; rnk[rx]++; }
}

3.10 Shortest Path (Unweighted) via BFS

In one sentence: For unweighted graphs, BFS from a source gives shortest paths measured in number of edges.

Key rules Unweighted shortest path: BFS, O(V+E). dist[v] = dist[u] + 1 on first discovery.
Worked Example — Shortest path from A in graph A–B, A–C, B–D, C–D, D–E
Step Action dist[] updated
init Start at A, dist[A] = 0 A: 0
visit A B and C first seen via A B: 1, C: 1
visit B D first seen via B D: 2
visit C D already visited (skip) —
visit D E first seen via D E: 3
Shortest path A → E = A → B → D → E (3 edges).
What if…? Add weights: A–B(10), A–C(1), C–B(1). BFS returns A→B (weight 10). True weighted shortest is A→C→B (weight 2). BFS fails on weighted graphs.

4.1 Linear vs Binary Search

In one sentence: Linear search scans every element (O(n)); binary search halves the search space each step (O(log n)) but requires sorted data.

Key rules Linear: O(n), unsorted OK. Binary: O(log n), needs sorted. Worst comparisons = ⌊log₂ n⌋ + 1.
C Code 
int linearSearch(int a[], int n, int key) {
    for (int i = 0; i < n; i++)
        if (a[i] == key) return i;
    return -1;
}

int binarySearch(int a[], int n, int key) {
    int lo = 0, hi = n - 1;
    while (lo <= hi) {
        int mid = lo + (hi - lo) / 2;
        if (a[mid] == key) return mid;
        else if (a[mid] < key) lo = mid + 1;
        else hi = mid - 1;
    }
    return -1;
}

4.3 Insertion Sort

In one sentence: Insertion sort builds a sorted prefix one element at a time by shifting larger elements right.

void insertionSort(int a[], int n) {
    for (int i = 1; i < n; i++) {
        int key = a[i];
        int j = i - 1;
        while (j >= 0 && a[j] > key) {
            a[j + 1] = a[j];
            j--;
        }
        a[j + 1] = key;
    }
}

4.4 Bubble Sort

In one sentence: Bubble sort repeatedly swaps adjacent out-of-order elements until no swaps are needed. 

void bubbleSort(int a[], int n) {
    for (int i = 0; i < n - 1; i++) {
        int swapped = 0;
        for (int j = 0; j < n - i - 1; j++) {
            if (a[j] > a[j + 1]) {
                int t = a[j]; a[j] = a[j + 1]; a[j + 1] = t;
                swapped = 1;
            }
        }
        if (!swapped) break;
    }
}
Worked Example — Sort [5, 1, 4, 2, 8]
Pass Comps Swaps Array after
1 4 3 [1, 4, 2, 5, 8]
2 3 1 [1, 2, 4, 5, 8]
3 3 0 → break [1, 2, 4, 5, 8]
Comparisons = 10, swaps = 4.

4.5 Selection Sort

In one sentence: Selection sort repeatedly finds the minimum of the unsorted region and swaps it into place.

void selectionSort(int a[], int n) {
    for (int i = 0; i < n - 1; i++) {
        int minIdx = i;
        for (int j = i + 1; j < n; j++)
            if (a[j] < a[minIdx]) minIdx = j;
        if (minIdx != i) {
            int t = a[i]; a[i] = a[minIdx]; a[minIdx] = t;
        }
    }
}
Worked Example — Sort [64, 25, 12, 22, 11]

1 12 at idx 2 yes [11, 12, 25, 22, 64]
2 22 at idx 3 yes [11, 12, 22, 25, 64]
3 25 at idx 3 no [11, 12, 22, 25, 64]
Comparisons = 10, swaps = 3.

4.6 Merge Sort

In one sentence: Merge sort splits the array in half, sorts each half recursively, then merges them back together.

Key rules Recurrence: T(n) = 2T(n/2) + O(n) → O(n log n) (Master Case 2). Stable. O(n) aux. 
void merge(int a[], int l, int m, int r) {
    int n1 = m - l + 1, n2 = r - m;
    int L[n1], R[n2];
    for (int i = 0; i < n1; i++) L[i] = a[l + i];
    for (int j = 0; j < n2; j++) R[j] = a[m + 1 + j];
    int i = 0, j = 0, k = l;
    while (i < n1 && j < n2)
        a[k++] = (L[i] <= R[j]) ? L[i++] : R[j++];
    while (i < n1) a[k++] = L[i++];
    while (j < n2) a[k++] = R[j++];
}

void mergeSort(int a[], int l, int r) {
    if (l < r) {
        int m = l + (r - l) / 2;
        mergeSort(a, l, m);
        mergeSort(a, m + 1, r);
        merge(a, l, m, r);
    }
}
Worked Example — Sort [38, 27, 43, 3, 9, 82, 10] 
Split:  [38,27,43]  [3,9,82,10]

4.7 Quick Sort

In one sentence: Quick sort picks a pivot, partitions the array around it, then recursively sorts the partitions.

int partition(int a[], int lo, int hi) {
    int pivot = a[hi];
    int i = lo - 1;
    for (int j = lo; j < hi; j++) {
        if (a[j] <= pivot) {
            i++;
            int t = a[i]; a[i] = a[j]; a[j] = t;
        }
    }
    int t = a[i + 1]; a[i + 1] = a[hi]; a[hi] = t;
    return i + 1;
}

void quickSort(int a[], int lo, int hi) {
    if (lo < hi) {
        int p = partition(a, lo, hi);
        quickSort(a, lo, p - 1);
        quickSort(a, p + 1, hi);
    }
}
Worked Example — Sort [10, 7, 8, 9, 1, 5] (pivot = last)
Level Segment Pivot After partition
1 [10, 7, 8, 9, 1, 5] 5 [1, 5, 8, 9, 7, 10], p = 1
2 right [8, 9, 7, 10] 10 [8, 9, 7, 10], p = 3
3 left [8, 9, 7] 7 [7, 8, 9]
Sorted: [1, 5, 7, 8, 9, 10].
What if…? Sorted input + last-element pivot → maximally unbalanced partitions → O(n²). Fix: randomized pivot or median-of-three.

4.8 Heap Sort

In one sentence: Heap sort builds a max-heap, then repeatedly extracts the maximum to the end of the array.

void heapify(int a[], int n, int i) {
    int largest = i, l = 2*i + 1, r = 2*i + 2;
    if (l < n && a[l] > a[largest]) largest = l;
    if (r < n && a[r] > a[largest]) largest = r;
    if (largest != i) {
        int t = a[i]; a[i] = a[largest]; a[largest] = t;
        heapify(a, n, largest);
    }
}

void heapSort(int a[], int n) {
    for (int i = n/2 - 1; i >= 0; i--) heapify(a, n, i);
    for (int i = n - 1; i > 0; i--) {
        int t = a[0]; a[0] = a[i]; a[i] = t;
        heapify(a, i, 0);
    }
}

Extract 3 [1, 3, 4, 5, 10]

Quick Revision Bullets

Module 3 — Must Remember

  • BST: left < node < right. Inorder = sorted. Search = O(h).
  • AVL: |BF| ≤ 1. Four rotations: LL, RR, LR, RL.
  • Threaded tree: NULL pointers → inorder threads. O(1) traversal space.
  • Trie: O(m) search, independent of word count. Prefix search native.
  • Heap: array-backed complete tree. Build = O(n). Insert/extract = O(log n).
  • Hash: O(1) avg. Chaining vs open addressing. Prime table size. α = n/m.
  • BFS = queue = shortest path. DFS = stack = cycle, topo.
  • Topo sort only for DAGs. Kahn's = BFS-based, O(V+E).
  • Union-Find + path compression + union by rank = O(α(n)) ≈ O(1).

Module 4 — Must Remember

  • Binary search needs sorted data. Linear works on anything.
  • Stable: insertion, bubble, merge, radix, bucket. NOT stable: selection, quick, heap.
  • In-place: insertion, bubble, selection, quick, heap. NOT: merge, radix, bucket.
  • Adaptive: insertion, bubble. NOT: selection, merge, quick, heap.
  • O(n log n) guaranteed: merge, heap. Quick is avg O(n log n), worst O(n²).
  • Quick worst = sorted input + bad pivot. Fix: random / median-of-three.
  • Merge = stable + worst-case guarantee. Heap = O(1) space + worst-case guarantee.
  • Radix/bucket beat O(n log n) only for integer keys with small range.
  • Master Theorem: compare f(n) with n^log_b a.
  • DP = overlapping subproblems + optimal substructure. LCS = O(mn).
